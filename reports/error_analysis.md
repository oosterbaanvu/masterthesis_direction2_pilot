# Error analysis and validity threats

**Basic checks already cover much of the easy error population.** All missing, invalid numerical-type and invalid-code injections are found by the applicable contracts. That leaves little justification for an LLM to rediscover those rules. Gross scale and plausible substitutions need separate interpretation: historical envelopes find many large deviations, but an in-domain replacement often preserves every univariate constraint. Bank's previous/outcome relationship catches some swaps. This identifies a bounded gap, not evidence that generated rules can close it.

**Off-label findings are not confirmed false errors.** Multicolumn violations flag all implicated columns, so untouched partners can be useful context even when only one cell was injected. Historical envelopes additionally flag naturally extreme or shifted observations. Counts outside injected positives are workload, never definitive real-error false positives. No independent adjudication was manufactured.

**The first expanded scale labels were invalid.** A string comparison counted zero multiplication as `0 -> 0.0`. That run is excluded. Final injections require semantic numeric change before assigning a value, realize 28,541/29,308 selected changes and retain 18 partial cases. Failed attempts and raw logs remain inspectable. This correction prevents a formatting-only “success,” rather than improving a method against altered labels.

**Tax and Cars expose normalization dependence.** Tax has 121,219 strict differences; 118,253 disappear under narrowly specified rate/ZIP equivalence. The remaining 2,966 differences are not automatically independently verified substantive errors; Pilot 1's more extensive provenance analysis found additional quote/representation issues. Cars has 820 strict differences but only 110 after numeric equivalence; a completeness score of 1.0 on those 110 is a missingness sanity result, not a general detection achievement. Restaurant excludes 30 class-label changes and retains 125 eligible differences, all caught by completeness, alongside 31 off-reference alerts. Rayyan is not accuracy-scored.

**SEC targets constraint participation, not exclusively corrupted cells.** Ordinary contributors are labelled alongside the changed total. Blank row names produce ambiguous coordinates; a truncated RSU/PSU row name is unresolved; one base has zero `errNum` but nonempty types. There are no target-clean counterparts from which this pilot can infer a different gold task. The 370 byte-identical cross-condition bases and shared issuers also limit independence. Bootstrap resamples bases, never individual cells or variants; broader issuer-level dependence is not eliminated.

**Accounting formatting changes lexical outcomes.** The conservative parser supports `(163)` but not ordinary `$(163)`. This documented baseline weakness is preserved; an explicit dollar-symbol sensitivity changes 28–29/208 lexical table outputs and 31–35/208 missing-heuristic outputs, with mixed F1 effects. No best parser was selected after looking at final labels. This is a reason to improve and separately validate a financial adapter before a thesis comparison, not to claim lexical checks represent all conventional financial controls.

**Source shift can dominate alerts.** An envelope fitted on Bank delivery 1 gives 16 cell alerts on its 7,763 training rows, 21,272 on 4,374 delivery-2 rows and 33,436 on 6,685 delivery-3 rows. Changing macroeconomic indicators explain much of this workload. There are no DQ error labels for these deliveries; alert volume is not detection accuracy. Low development violation rates cannot by themselves establish a rule's deployment suitability.

**Qualification is not semantic verification.** Evidence-presence, syntax, execution, deduplication and whitespace invariance are enforceable software checks. They cannot verify the truth of an alleged business relationship. A 1% violation screen can reject a useful rule on genuinely dirty data, and can accept an invalid rule that happens not to fire. Candidate-level useful/invalid labels, false rejection and C/D detection losses remain **NOT_RUN**, not zero, because no experimental LLM candidates or independent semantic adjudications exist.

**Other threats remain open.** Public benchmark memorization, prompt sensitivity and model stochasticity are not measured without live inference. Historical controls include explicitly attributed pre-existing source knowledge; their provisional domains are not universal semantics. Three UCI domains are not independent evidence of enterprise-wide transfer. Repeated seeds/rates/fields and shared records are dependent. Optional Kaggle sources, unresolved redistribution rights, inaccessible recent full papers and the unseen recent acceptance-layer reproduction package constrain the scientific verdict. No numerical comparison resolves those limitations.
