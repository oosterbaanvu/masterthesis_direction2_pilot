# Literature and novelty gate — search to 21 October 2026

The broad contribution is already crowded. Generating executable rules, executing/repairing them, deduplicating them, and applying acceptance filters are established ideas. A governed service is valuable engineering, not scientific novelty. The more defensible possible question is whether qualification preserves **incremental, substantively useful detections beyond an existing control suite under source shift**, with independently adjudicated errors and frozen candidates. This pilot does not establish priority for even that narrower question.

Functional dependencies and denial constraints are longstanding discovery/validation concepts. HoloClean and Auto-Test describe that literature; this pilot implements an FD violation check, not a new discovery algorithm. An attempted denial-constraint PDF URL returned HTML, so it is **not** counted as a read paper. Full-text access and citation correction matter more than inflating a reference count.

## Are the proposed ingredients already solved?

| Ingredient | What the inspected evidence establishes | Remaining claim that would need evidence |
|---|---|---|
| Executable SQL quality-rule generation | Explicit LLM-DQR implementation; Akella supports executable validators and discusses SQL | No novelty by itself |
| Execution/debugging | Both LLM pipelines include it | Whether execution-safe rules are semantically reliable in a specific new setting |
| Deduplication/conflict filtering | LLM-DQR two-stage deduplication; Akella conflict/rubric filters | New algorithm or materially different failure population must be demonstrated |
| Usefulness beyond existing controls | Auto-Test explicitly supports augmentation; established controls already cover many benchmark positives | Incremental **substantive** detection conditional on a frozen financial control suite |
| Empirical acceptance/rejection | Auto-Test candidate assessment/optimization; 2026 Bayesian abstract directly addresses promotion decisions | Candidate-level semantic evidence, independent error labels and source-shift behavior absent from closest work must be verified |
| Unseen tables/source change | Auto-Test unseen-table objective; Akella cross-domain evaluations; Deequ historical monitoring | Frozen LLM candidates transferred across source changes are not established by this pilot or disproved as prior art |
| Fewer false alerts while retaining detection | Auto-Test explicitly optimizes this tradeoff; Akella risk filters; Bayesian abstract reports false promotions | Not a novel question without a sharply different estimand, setting or method |

## Search boundary and interpretation

Primary user-supplied papers were investigated first, followed by publisher metadata queries restricted to 2024–21 October 2026, ACL metadata and official implementations. `literature_search.json` preserves screened titles/DOIs, query response hashes, failures and a discarded wrong Auto-Test DOI. Repository/primary-document hashes and URLs are pinned in `config/literature_sources.json`; PDFs remain ignored and read-only. This is a bounded feasibility review, **not** an exhaustive systematic literature review. Two bibliographic queries failed, important publisher PDFs remain inaccessible, and the very recent Bayesian article requires full review before any positive novelty claim.

No numerical literature finding is presented as newly reproduced unless it comes from the released SEC artifacts rescored in this repository. In particular, LLM-DQR, Akella, Auto-Test and Bayesian verification performance was not reproduced.
