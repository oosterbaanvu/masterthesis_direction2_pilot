# Candidate-rule experiments: what ran and what remains unavailable

**No new research-model candidate set exists.** New paid and free-endpoint inference calls both number zero. There is no configured research endpoint, and the user will choose a model after reviewing the recommendation. No Codex output or handwritten fixture is represented as an experimental model response.

## Actual frozen-input comparison

Fifty-seven handwritten, provenance-labelled GX fixtures were frozen across four LeDQeR sources. The same candidates feed technical execution and the original labelled greedy selection. All executed; 57 original/independent TP/FP/FN comparisons match. This verifies integration and illustrates selection behavior only. It does **not** satisfy the decisive real-LLM comparison.

At precision threshold 1, Flights retains all 424 technical-union labelled evaluation hits. Beers retains 599 while reducing the union's 271 unlabelled/reference-negative flags to zero. Hospital rejects all fixtures: it removes 257 reference-negative flags but loses all 6 labelled hits. Tax produces no hits. Changing the threshold to zero allows the Hospital fixture again. Labels are author-supplied, and the fixture formats are not established semantic truths. These outcomes cannot demonstrate that a proposed LLM qualification method improves real data quality.

| D No additional rules | Preserve exactly the existing conventional control suite | Parent deterministic/service evidence preserved. No fabricated new A–D comparison |

The core provenance guard requires provider, model revision, prompt hash, response hash and source partition. It rejects handcrafted fixtures and reserved-source development inputs. Actual response-cache/cost controls must be adapted and checked for the chosen provider before any future call; a cost proposal alone is not an executed cap.

C is deliberately limited. Documentation must be frozen **before** generation and indexed by a trusted normalized executable-contract signature; a model's own evidence citation cannot certify itself. No human rule-validity answer is supplied to the selector. A manually adjudicated per-candidate entailment label would be additional supervision and must be reported as such. A zero observed violation rate does not prove validity. Unknown signatures, missing scope or unstable formatting lead to abstention, not automatic acceptance. This exact-contract baseline is not claimed as a novel algorithm and can be redundant with a complete existing control suite.

## Outcomes and remaining gate

The outcome counter includes both extra labelled hits beyond baseline controls and labelled detections lost through selection. Additional unlabelled findings are workload, not automatically false positives. The independent-rule semantic metrics require actual reviewer labels and remain **NOT_MEASURED**. Useful-rule rejection requires a predefined counterfactual usefulness criterion and full-candidate evaluation, rather than measuring accepted rules alone.

Published-output reuse was investigated: LeDQeR's complete inspected history contains no generated rule sets; FinRule's acquired tasks contain inference scripts and label/injection artifacts rather than reusable candidate-rule responses. Existing SEC predictions can be rescored and already were, but are diagnosis outputs, not executable candidates for A–D. None can legitimately fill the missing experiment.

The inference gate is concrete: select a proposed model and cap in `model_access_and_costs.md`, configure its research credential securely, verify provider account pricing/parameters and dataset transmission rights, and freeze the candidate/input manifests before selection. No payment or provider choice is inferred from elapsed time. The four-arm result remains unknown.
