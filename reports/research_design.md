# Protocol v1 — fixed before Pilot 2 outcome execution

Question: To what extent can evidence-based validation improve the detection reliability and deployment suitability of automatically generated data-quality rules on unseen tabular data?

This is an exploratory feasibility pilot, not a preregistered confirmation. Pilot 1 reports and two SEC examples were inspected during source qualification. No new experimental results existed when this protocol was written. Freeze hashes before experiment execution. A separate untouched SEC partition is never scored by new methods in this pilot.

SEC groups are the first five digits of original table IDs; SHA-256 of `dq-rules-pilot2-v1:<id>` modulo 100 assigns <60 development, 60–79 exploratory, >=80 reserved. All corruption variants stay together. Structural annotation audit across the release is evaluation-only; manual inspection uses development tables. No filenames, JSON annotations, or clean tables enter detector inputs. Retrospective reproduction of published outputs uses all released tables to validate the official evaluator; this is not a new holdout result. Do not use that reproduction to select new rules.

Tracks: (1) SEC financial logical-inconsistency benchmark, conditional on annotation/rights audit; (2) regular UCI contract and controlled-injection experiments; (3) source-specific published dirty/clean differences; (4) operational service. No pooled F1. Regular sources exclude prediction targets. Fit statistical envelopes and type expectations on development rows only, with exact duplicate records grouped. Three seeds (11/12/13), rates 1/2% of one column's evaluation rows, and missing/type/scale/plausible-swap families. These are bounded error populations, not a model of natural errors. Log realized changes; unchanged proposals fail. Statistical flags on untouched cells are unverified burden, not confirmed errors. Use injected-positive recall and precision relative to injected labels, with absolute denominators and off-label alerts; no independently adjudicated real-error precision claim.

A: generic completeness/type controls plus source-evidenced domains, keys, ranges and cross-field rules. Historical envelope checks separately labelled. SEC uses conservative lexical numeric checks only: no inferred financial arithmetic without a contract. B: released direct-model outputs (retrospective reproduction) and live detection only with credentials + explicit budget. C: model candidates frozen before qualification; D: exactly those candidates after static/schema, duplicate, execution, evidence and formatting checks, then development alert-fraction screen. Execution success is not semantic validity. C/D live comparison is NOT_RUN without authorized inference; deterministic qualification fixtures are engineering tests only. No fictitious model candidates or predictions.

Primary scientific comparison: C/D paired cell-level F1 when trustworthy locations exist, precision and recall separately, extra labelled detections beyond A, coverage lost and false rejection of independently adjudicated useful rules. Secondary: table binary F1, fixed error-type macro-F1, workload, execution/acceptance rates, costs and runtime. Ambiguous SEC row-name locations are not uniquely localizable cells. Official compatibility metrics and corrected metrics are both reported; never relabel recall as precision. SEC bootstrap unit is base table, grouping corruption settings. UCI repetitions reuse rows: report descriptive ranges, not independent-source confidence intervals. Published pairs: strict differences plus explicit numerical normalization sensitivity; Tax ZIP padding is a representation-specific sensitivity, not blanket numeric typing. Rayyan accuracy is withheld absent adjudication. No uncertainty estimate implies independent dataset sampling.

Robustness: numeric representation transformations; repeated seeds/rates; error-family slices; source-shift descriptives; lexical SEC checks with/without missing-cell heuristics (the latter are not automatically justified). Do not repair filters after exploratory outcomes. Final confirmatory labels remain reserved for a separately reviewed protocol.

Decision rubric fixed before outcome interpretation: novelty (0 established integration, 1 unresolved narrow empirical question, 2 clear new question supported by full-text review); ground truth (0 unusable, 1 conditional, 2 independently adjudicated); empirical C/D evidence (0 absent, 1 bounded exploratory, 2 convincing); feasibility (0 external blocker, 1 bounded executable, 2 complete); engineering (0 absent, 1 demonstrated, 2 governed realistic integration). No automatic summed winner: GO requires novelty>=1, truth>=1, C/D>=1 and feasible resources. CONDITIONAL GO may be a direction requiring those gates, never a claim they passed. Compare Pilot 1 on the same rubric using its verified branch reports as historical evidence, without comparing unrelated F1 and budgeted recall.

Nine-month scope if viable: months 1–2 novelty, benchmark/adjudication and protocol; 3–4 bounded generation and frozen candidates; 5–6 qualification ablations and source shift; 7 confirmatory evaluation; 8 analysis and demonstrator; 9 writing. Scientific contribution is evidence about useful-rule retention versus misleading-alert rejection conditional on existing controls; integration is a separate artifact.
